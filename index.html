    Manual de uso: cómo instalar, compilar y correr el proyecto, qué archivo se ejecuta y qué produce.

    Qué hace

    Kynova es un compilador. Lee un archivo .kyn, comprueba que esté bien escrito y que los tipos tengan sentido, y escribe su traducción a Chapín en un archivo .gt. No ejecuta el programa.

    Manual paso a paso

    QuéCuál
    El programa que se ejecuta./kynova (aparece al correr make)
    El archivo que se le dasalida.kyn (o cualquier .kyn)
    El archivo que produceChapin.gt
    Dónde se correEn una terminal, dentro de la carpeta del proyecto (donde está el Makefile)

    1. Instalar las herramientas (solo la primera vez). Comandos en la sección siguiente.

    2. Abrir la terminal en la carpeta del proyecto.

    cd ruta/a/kynova
ls                  # debe verse Makefile, src, tests y salida.kyn

    3. Compilar. Crea el programa ./kynova. Si no sale ningún error, está listo.

    make

    4. Comprobar que el archivo es válido. Debe terminar diciendo Resultado: programa VÁLIDO.

    ./kynova -q salida.kyn

    5. Generar el Chapín. Escribe Chapin.gt y avisa con «Chapín generado en Chapin.gt».

    ./kynova -c Chapin.gt salida.kyn

    6. Entregar Chapin.gt al grupo de Chapín. Para traducir otro programa, cambia salida.kyn por tu archivo.

    7. (Opcional) Correr las pruebas. Debe terminar con «Pruebas: 23 OK, 0 fallidas».

    make test

    Qué se ve al correrlo

    Archivo válido: el compilador termina con Resultado: programa VÁLIDO y el código de salida 0. Con -c escribe el Chapín.

    Archivo con un error: dice el archivo, la línea, la columna y el tipo de error, y no genera el Chapín. Ejemplo:

    ./kynova tests/invalid/04_falta_ryan.kyn
tests/invalid/04_falta_ryan.kyn:4:1: error sintáctico: fin de archivo inesperado, se esperaba 'ryan'
Resultado: programa INVÁLIDO (0 error(es) léxico(s), 1 sintáctico(s))

    Qué hay que tener instalado

    Un compilador de C (gcc o clang), Flex 2.6 o más nuevo, Bison 3.6 o más nuevo y make.

    # macOS (el bison que trae el sistema es muy viejo)
brew install bison flex

# Ubuntu / Debian
sudo apt install build-essential flex bison

# Windows: usar WSL (Ubuntu) y seguir los pasos de Linux

    Todos los comandos

    make                                # compila y crea el programa ./kynova
./kynova salida.kyn                 # revisa el archivo: muestra árbol y símbolos
./kynova -q salida.kyn              # solo el veredicto (VÁLIDO o INVÁLIDO)
./kynova -t salida.kyn              # además muestra los tokens
./kynova -c Chapin.gt salida.kyn    # además escribe la traducción en Chapin.gt
make test                           # corre los 23 casos de prueba
    OpciónQué hace
    -tmuestra los tokens que reconoce Flex
    -amuestra el árbol que arma Bison, con tipos
    -smuestra la tabla de símbolos (Gene Bank)
    -d ARCHguarda el árbol en formato Graphviz (para hacer una imagen con dot)
    -qsolo errores y el resultado final
    -c ARCHgenera la traducción a Chapín en ese archivo
    -hayuda

    El programa termina con 0 si el archivo es válido, 1 si tiene errores y 2 si se usó mal (archivo que no existe u opción desconocida). El Chapín solo se genera cuando el archivo es válido.

    Qué es cada archivo

    ArchivoPara qué sirve
    salida.kynEl programa de ejemplo que mandó el grupo 6 (Andante → Kynova). Es lo que se compila.
    Chapin.gtLa traducción a Chapín de salida.kyn. Es lo que se le entrega al grupo de Chapín. Se regenera con -c.
    kynovaEl compilador ya armado. Aparece al correr make.
    MakefileLas recetas: make, make test, make demo, make ast-png y make clean.
    src/kynova.lLas reglas de Flex: qué es una palabra reservada, un número, un comentario. Aquí se cambia el vocabulario de Kynova.
    src/kynova.yLa gramática de Bison: en qué orden pueden venir las piezas. Construye el árbol.
    src/lexer.hLo que comparten el léxico, el parser y main.c.
    src/ast.h, ast.cLos nodos del árbol, cómo se crean y cómo se imprimen.
    src/symtab.h, symtab.cLa tabla de símbolos (Gene Bank): variables, tipos, alcance y usos.
    src/semantic.h, semantic.cEl análisis semántico: declaraciones y compatibilidad de tipos.
    src/chapin.h, chapin.cEl traductor a Chapín. Aquí se cambia cómo sale cada palabra en Chapín.
    src/main.cEl programa principal: lee las opciones y llama a cada fase en orden.
    tests/valid/5 programas que deben aceptarse.
    tests/invalid/18 programas que deben rechazarse, uno por cada tipo de error.
    tests/run_tests.shEl script que usa make test.
    build/Archivos que genera la compilación. No se editan.
    ast.pngImagen del árbol (se hace con make ast-png, requiere Graphviz).
    Lenguajes Compiladores.xlsxLa tabla que compara el vocabulario de todos los grupos.
    README.mdLa documentación completa del proyecto.
    presentacion/index.htmlEsta página. Se abre con doble clic en el navegador y necesita internet.
    presentacion/Dockerfile, nginx.confLo que usa Coolify para publicar la página en un servidor. Los pasos están en DEPLOY.md.

    Preguntas frecuentes

    ¿Qué significa «error léxico», «sintáctico» o «semántico»?

    Dice qué fase lo atrapó: una pieza que no existe, piezas en mal orden, o algo bien escrito pero sin sentido, como mezclar tipos. Mira el Glosario.

    ¿Dónde cambio una palabra de Kynova?

    En src/kynova.l (la palabra) y src/kynova.y (si cambia la gramática).

    ¿Dónde cambio cómo sale algo en Chapín?

    En src/chapin.c. Después corre make y ./kynova -c Chapin.gt salida.kyn.

    make dice «bison: command not found» o «flex: command not found».

    Falta instalarlos. En macOS: brew install bison flex. En Ubuntu: sudo apt install build-essential flex bison.

    make falla en macOS por la versión de Bison.

    El Bison del sistema es muy viejo (2.3). Instala el de Homebrew con brew install bison; el Makefile lo encuentra solo.

    «./kynova: No such file or directory».

    Todavía no se compiló o estás en otra carpeta. Corre make dentro de la carpeta del proyecto.

    ¿Por qué no se genera el Chapín?

    Solo se genera si el archivo es válido. Corre sin -q para ver el error y su línea.
